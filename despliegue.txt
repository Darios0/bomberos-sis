Manual de Réplica: Despliegue de BOMBEROS SIS en CentOS 9
1. Preparación de la Red y Seguridad del Sistema (CentOS 9)
CentOS 9 bloquea por defecto el tráfico de Docker. Antes de encender los contenedores, debes configurar el enrutamiento y las zonas del firewall de forma correcta:
bash

# Habilitar el reenvío de paquetes IP en el sistema operativo
sudo sysctl -w net.ipv4.ip_forward=1

# Permitir en el Firewall que Nginx realice conexiones de red internas (SELinux)
sudo setsebool -P httpd_can_network_connect 1

# Abrir los puertos físicos de la máquina virtual hacia la red externa (Windows)
sudo firewall-cmd --zone=public --add-port=80/tcp --permanent
sudo firewall-cmd --zone=public --add-port=3001/tcp --permanent
sudo firewall-cmd --reload

# Forzar reinicio limpio del servicio de Docker
sudo systemctl reset-failed docker
sudo systemctl restart docker

Usa el código con precaución.
2. Archivo de Orquestación Definitivo (docker-compose.yml)
El contenedor del servidor backend debe exponer obligatoriamente el puerto 3001 hacia el exterior mediante la directiva ports (no expose) para que el navegador de Windows pueda consumir la API.
Ruta: /opt/bomberos-sis/docker-compose.yml
yaml

services:
  postgres:
    image: postgres:16-alpine
    container_name: bomberos_db
    restart: unless-stopped
    environment:
      POSTGRES_USER: ${DB_USER:-postgres}
      POSTGRES_PASSWORD: ${DB_PASSWORD:-change_me_in_production}
      POSTGRES_DB: ${DB_NAME:-bomberos_db}
    volumes:
      - postgres_data:/var/lib/postgresql/data
    networks:
      - bomberos_net
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${DB_USER:-postgres}"]
      interval: 10s
      timeout: 5s
      retries: 5

  servidor:
    build:
      context: .
      dockerfile: server/Dockerfile
    container_name: bomberos_server
    restart: unless-stopped
    environment:
      DATABASE_URL: postgresql://${DB_USER:-postgres}:${DB_PASSWORD:-change_me_in_production}@postgres:5432/${DB_NAME:-bomberos_db}
      JWT_SECRET: ${JWT_SECRET:-change_me_in_production}
      PORT: 3001
      NODE_ENV: production
    volumes:
      - server_logs:/var/log/bomberos
    networks:
      - bomberos_net
    depends_on:
      postgres:
        condition: service_healthy
    ports:
      - "3001:3001" # <- Mapeo físico obligatorio para producción
    healthcheck:
      test: ["CMD", "wget", "--no-verbose", "--tries=1", "--spider", "http://localhost:3001/api/health"]
      interval: 30s
      timeout: 10s
      retries: 3

  nginx:
    image: nginx:alpine
    container_name: bomberos_nginx
    restart: unless-stopped
    ports:
      - "80:80"
    volumes:
      - ./nginx/bomberos.conf:/etc/nginx/conf.d/bomberos.conf:ro
      - ./client/dist:/usr/share/nginx/html:ro
    networks:
      - bomberos_net
    depends_on:
      - servidor

volumes:
  postgres_data:
  server_logs:

networks:
  bomberos_net:
    driver: bridge
    ipam:
      config:
        - subnet: 172.20.0.0/16

Usa el código con precaución.
3. Configuración del Servidor Web (bomberos.conf)
Se corrigieron dos errores críticos: la palabra Sserver por server, y se reemplazó la variable inexistente $date_iso8601 por el formato estático para evitar que Nginx colapsara al iniciar. Además, se desactivó el bloqueo de IPs privadas.
Ruta: /opt/bomberos-sis/nginx/bomberos.conf
nginx

server {
    listen 80;
    server_name _;

    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api {
        proxy_pass         http://bomberos_server:3001; # Nombre exacto del contenedor backend
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        
        proxy_read_timeout    120s;
        proxy_connect_timeout 10s;
    }

    location /health {
        access_log off;
        default_type application/json;
        return 200 '{"status":"healthy"}'; # Formato limpio sin variables conflictivas
    }
}

Usa el código con precaución.
(Nota: El archivo bomberos-ssl.conf debe ser removido o sacado de la carpeta /nginx si no se van a usar certificados SSL dominio/HTTPS de forma local).

5. Comandos de Control Diario
Una vez todo esté configurado, los comandos para administrar tu aplicación en el día a día son:

    Encender todo el sistema: sudo docker compose up -d
    Apagar el sistema por completo: sudo docker compose down
    Ver el estado de salud de los componentes: sudo docker ps
    Monitorear errores en tiempo real (Backend): sudo docker logs -f bomberos_server
